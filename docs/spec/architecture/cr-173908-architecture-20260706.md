## 2. Mock / 信任层隔离策略

### 2.1 Oracle 侧（已存在范式，复用）
`OracleAdapter.t.sol` 已用 `MockAggregator` 模拟 Chainlink Data Feed，纯本地。本需求**不改动**此范式，作为可复用模板。

### 2.2 HumanHouse 侧（stub 信任层）
依据决策 D1/D3：
- `_verifyWorldId()` **保持返回 `true`**，作为"已完成信任层"的 stub。
- 测试**不传入** World ID 证明参数（与现有 `humanHouse.vote(1, true)` 写法一致）。
- 若未来真实集成，仅需将 stub 替换为可注入 `MockWorldID` 地址（本期**不实现** D3 暂缓），业务测试无需重写。

> 设计要点：业务逻辑的测试与信任层解耦。信任层缺失以 stub 兜底，业务路径（押金经济、状态机、防重复）独立可测。

## 3. 关键设计决策

| 决策 | 理由 |
|------|------|
| 不引入 ffi / 真实 proof | 保证零外部 RPC 与 CI 可跑（约束 1） |
| 不重复编写已存在的业务测试 | 核对源码确认 `HumanHouse.t.sol`/`GovCrownToken.t.sol` 已覆盖核心路径，聚焦真正缺口 |
| 治理骨架用 harness 而非真实 Governor | TokenHouse 未实现，仅验证委托链路 + 预留阈值快照 helper |
| 部署 dry-run 复刻脚本逻辑于测试 | 部署所有权转移是高危操作，需不变量回归锚点 |
| GAP-1 用 `pass` 占位守卫 | 显式暴露缺口且不阻塞 CI（failed 会误伤） |

## 5. 零外部 RPC 保证

- 全部测试运行于 Foundry 内置 anvil，无 `--rpc-url` 指向公共节点。
- `Makefile` `test` 目标即 `forge test -vvv`，无环境变量依赖外部 API。

## 6. 缺口对架构的影响

### GAP-1（关键）
`executeDispute` 当前仅处理押金（退款/没收），**未调用** `resolveMarket(opposite)`（OracleResult 通过时）或隐藏市场（MarketContent 通过时）。与设计文档 `bicameral-governance-design.md §3.2` 不符。
- 测试影响：占位守卫 `test_GAP1_ExecuteDisputeMissingResolutionEffect` 记录此缺口，`pass` 不阻塞。
- 修复影响：实现裁决副作用后，该守卫应升级为真实断言（调用 `market.resolveMarket` 后状态变更）。

### GAP-2（次要）
`HumanHouse` 继承 `Pausable`，`raiseDispute/vote` 带 `whenNotPaused`，但**无 external `pause()/unpause()`**。
- 测试影响：`paused` 路径无法本地触发，相关用例从测试集中剔除（非遗漏，是死代码）。
- 修复影响：补充 onlyOwner `pause()/unpause()` 后，可补 paused 回滚用例。
